# Lane 0: the run report and the fast-forward test

- **Run report** (step 8, `pnpm --filter @forkling/mind run-report --world <clone> --from <date> --to <date>`): PR #181, merged. `apps/mind/src/run-report.ts`, tests `apps/mind/test/run-report.test.ts` on fixture worlds. Reads files, tick logs and git history; writes nothing. Projects, threads, visitors, tool requests and tools read "none yet" until their steps land.
- **Fast-forward** (`pnpm --filter @forkling/mind fast-forward --world <copy> --days 7 --cap 3`, or `--clone-from <url>`): branch `claude/v4-0-fast-forward`. `apps/mind/src/fast-forward.ts` (the run), `fast-forward-cli.ts`, `fast-forward-fakes.ts` (the `--dry-run` model and web), tests `apps/mind/test/fast-forward.test.ts`.
  - Refuses a world with a git remote; `--clone-from` clones and removes `origin`. No git commits, no GitHub client: a full work's pull request is written straight into `works/<id>/` (only that folder).
  - `createLoop` and the build worker (expand, found, tinker) on a fake clock moved by `nextDelayMs`; the worker gets a turn every simulated minute. The model goes through the normal budget guard plus a run cap that refuses calls once spent; the run stops at the next tick.
  - Web: the real fetcher and allowlist; every request is watched (a host off the allowlist is a rail broken) and kept a real second apart per host.
  - Rails checked: a request off the allowlist, a model other than Haiku/Sonnet 5.5, a paid call while asleep (except the sleep rewrite), reads over the daily quota, the month's spend over its cap, a work pull request outside its folder, the run far over its cap.
  - Pass: no crashes (tick or build worker errors caught), no rails broken, each day's spend under the month cap / days in month, something visual (a work, sketch, project session, found or expand) every simulated day. Exit 0 on a pass, 1 on a fail, 2 when it could not start.
  - Writes `summary.md`, `run-report.txt` and `shots/` (work thumbnails from the browser check, project session shots) to `--out` or a temp dir, path printed. The summary names the engine commit.
  - Needs `ANTHROPIC_API_KEY` unless `--dry-run`. Speed: about 8 ms a tick on the template world (a simulated week is about 44,000 ticks), more on a bigger world, plus the real calls.
  - **`--sessions`** (R2's test, step 4): `pnpm --filter @forkling/mind fast-forward --world <copy> --days 7 --cap 3 --sessions` (default off, so the R1-style run is unchanged). Gives the loop `deps.sessions` (the `build` verb) and registers `createSessionHandler` on the build worker with the local runner (`createSandbox()`, the session-try wiring: `requireSandbox: false`, no git, no timelapse) on the fake clock. The session model goes through `cappedModel(...).session()`, so session turns count under the run cap and are refused once it is spent. `--dry-run --sessions` uses `fakeSessionModel` and `fakeSandbox` (no browser, no key) and a fake plan that builds "Colour clock".
  - Summary gains "Build sessions": count, cost in all and per session, the dearest, projects made and changed, session failures (and `later`s are not failures). Information only, as spec 8 and the plan add no pass rule for sessions, except one: **a single session over $1 fails the run** (Roman's 18 November 2026 rule for the live server; the summary says so). `FastForwardResult.sessions` carries the same numbers. Tests: `apps/mind/test/fast-forward.test.ts`, "a run with build sessions".
